# 项目问题诊断与修改方案

> 基于测试反馈 + 代码审阅整理。覆盖前端 Tab 污染、情绪拨盘辨识度、行程规划 0/1 POI、空 null 处理缺陷等问题。

---

## 一、问题清单（按严重程度排序）

### 🔴 P0 - 核心功能错误

#### 问题 1. 「行程规划」Tab 快速规划 bug

**现象**
- 点 🏫 **五道口** → 返回 **0 个 POI**（空行程，0 小时 0 分，¥0）
- 点 🍷 **三里屯** → 只返回 **1 个 POI**（postpost 咖啡厅）
- 点 🏬 **王府井** → 只返回 **1 个 POI**（Solitude 孤独招待所）

**根因（三重原因叠加）**
1. **数据地理分布极度不均**：30 个 POI 全部聚集在三里屯一带（经纬度 39.91~39.93, 116.44~116.46），五道口距离最近 POI 达 **10.89 km**
2. **步行速度过慢**：`helpers.py:52` 设 5km/h（即 12min/km），但 `itinerary_agent.py` 实际调用后效果相当于 20min/km 场景，五道口 → 最近 POI 需要 130+ 分钟，3 小时预算（180 分钟）加停留时间（45-120 分钟）根本放不下任何 POI
3. **POI duration_min 过长**：大多 POI 停留 90-180 分钟，选中一个就用掉 2-3 小时，第二个 POI 塞不进去

**根因链路**
- `api/itinerary.py:115-121` 硬编码 `stay_hours=3.0, mode="walk"`，无偏好输入
- `itinerary_agent.py:165-166` 严格时间约束：`travel_time + stay_time > remaining_time` 直接跳过
- `itinerary_agent.py:67` 主循环条件 `remaining_time > 30`，触发过早退出

---

#### 问题 2. 情绪拨盘推荐辨识度极低

**现象**
- 不同象限（热闹/安静/高能/静谧）返回的 top-5 几乎一样
- 同一象限内移动，结果无变化

**根因（三重原因叠加）**

1. **POI 数据层**：30 个 POI 中只有 **11 个（37%）带情绪标签**，19 个是"情绪中性"的，它们因为通用正向信号（好吃、氛围好、服务好）在所有情绪查询下都排进 top-5。
   - 情绪标签分布（重度失衡）：
     - 🔇 安静：5 个 (松鹤楼、Seesaw、Solitude、功德林、团结湖)
     - 🔊 热闹：5 个 (渝信川菜、跳海、火烧云、海底捞、木屋烧烤)
     - 😌 平和：3 个 (朝阳公园、美克洞学馆、团结湖)
     - ⚡ 高能：2 个 (Blue Note、胡桃里)

2. **Embedding 文本构造**：`vibe_agent.py:28-44` 把评论 + 标签 + 品类拼在一起，平均长度只有 7-9 词，情绪词只占 **10-15%**，被"好吃""咖啡""服务好"这类泛化信号稀释。

3. **前端 `moodVectorToText` 映射过粗**：`App.tsx:54-70` 用 `±0.5` 为阈值切 3×3 格子，**最多只能产生 9 种不同文本**。拨盘从 (0.6, 0.1) 拖到 (0.9, 0.4) 生成的是同一串文本，推荐结果自然一样。

#### 问题 3. 前端 Tab 间状态污染

**现象**
- 在「🎭 情绪拨盘」Tab 生成路线后，切到「🗺️ 行程规划」Tab，路线还在显示
- 看起来像是行程规划 Tab 自己生成的结果

**根因**
`App.tsx` 里以下 7 处渲染区块**都没有 `activeTab` gate**：

| 行号 | 渲染区块 | 当前 gate | 应有 gate |
|---|---|---|---|
| 298 | ItineraryCardGroup（路线卡片组） | 无 | `activeTab === "mood"` |
| 310 | MapView + 操作按钮区（大块紫粉区） | 无 | `activeTab === "mood"` |
| 441 | 休憩点面板 | 无 | `activeTab === "mood"` |
| 472 | 阴凉路段面板 | 无 | `activeTab === "mood"` |
| 508 | 推荐 POI 列表 + 生成路线按钮 | 无 | `activeTab === "mood"` |
| 661 | itinerary 卡片 | ✅ `activeTab === "itinerary"` | 正确 |
| 721 | 空状态提示 | `activeTab !== "chat"` | 保持 |

7 个 state 全是组件级全局（`recommendations, routes, selectedRoute, restPoints, showRest, climateSegments, showClimate, selectedIds, moodValue`），切 Tab 时不会清。

### 🟡 P1 - 健壮性缺陷

#### 问题 4. `decision_agent.py` 空值处理 bug

**现象**：之前你遇到的 `TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'`

**根因**：`decision_agent.py:245-248`
```python
lat = state.fields.get("location_lat", 39.931)   # ❌ key 从不存在，默认值永远生效（还不是bug，但意图错）
lon = state.fields.get("location_lon", 116.453)  # ❌ 同上，字段名和 DialogState 定义不符（只定义了 location）
hours = state.fields.get("time_budget", 3.0)     # ❌ key 存在但值为 None，返回 None 不是 3.0
budget = state.fields.get("budget")               # ❌ 无兜底，None 可能传到下游
```

`dict.get(key, default)` 只在 key 不存在时返回 default，key 存在但值为 None 时返回 None。而 `DialogState.__init__` 把所有字段预初始化为 None。

**文件**：`backend/app/data/mock/pois.json`

**操作**：
1. **新增 10 个 POI**（共 40 个）：

2. **为所有 40 个 POI 补齐情绪标签**，目标分布：
   - 安静向：10 个
   - 热闹向：10 个
   - 平和向：10 个

### 方案 B：后端算法优化（解决问题 2 算法层）

**文件**：`backend/app/agents/vibe_agent.py`

**修改**：

1. **改 embedding 文本构造（__init__，lines 28-44）**：把情绪标签权重拉高，通用词降权
   ```python
   # 情绪标签重复 3 次（放大信号）
   mood_keywords = self._extract_mood_tags(poi)
   text_parts.extend(mood_keywords * 3)
   # 类别和评论各放 1 次
   text_parts.extend(poi.get("demo_reviews", []))
   text_parts.append(poi.get("category", ""))
   ```
   其中 `_extract_mood_tags` 是新增私有方法，维护一个情绪词表 `{安静, 热闹, 高能, 静谧, 舒适, 浪漫, ...}`，只抽标签里匹配上的词。

2. **match 结果引入情绪轴分数加权**（lines 72-93）：用户文本包含的情绪关键词和 POI 情绪标签 Jaccard 相似度作为补偿分
   ```python
   vibe_overlap = len(set(user_mood_keywords) & set(poi_mood_tags)) / max(len(user_mood_keywords), 1)
   final_score = sim * 0.7 + vibe_overlap * 0.3
   ```

3. **去重机制（方案 C 的铺垫）**：top_k 时加入 category 多样性约束，避免 5 个结果里 3 个都是咖啡厅。

### 方案 C：前端拨盘映射升级（解决问题 2 前端层）

**文件**：`frontend/src/App.tsx`（函数 `moodVectorToText`，lines 54-70）

**修改**：把 3×3 离散映射改为**连续强度 + 连续方向**：
```ts
function moodVectorToText(v: MoodVector): string {
  const dist = Math.sqrt(v.x * v.x + v.y * v.y);
  const angle = Math.atan2(v.y, v.x);  // [-π, π]
  const parts: string[] = [];
  
  // 按角度选主情绪词（8 个方向）
  const direction = Math.round((angle / Math.PI) * 4 + 4) % 8;
  const dirWords = [
    ["安静", "独处"],      // 左 (-π): 安静极
    ["舒适", "惬意"],      // 左下
    ["静谧", "放松"],      // 下: 静谧极
    ["温和", "悠闲"],      // 右下
    ["活跃", "氛围"],      // 右 (0): 热闹极
    ["热闹", "聚会"],      // 右上
    ["高能", "刺激"],      // 上: 高能极
    ["独处", "沉静"]       // 左上
  ];
  parts.push(...dirWords[direction]);
  
  // 强度词根据 dist 叠加
  if (dist > 0.7) parts.push("强烈");
  else if (dist > 0.3) parts.push("温和");
  else parts.push("平淡");
  
  return parts.join(" ");
}
```
**效果**：32 种连续组合（8 方向 × 4 强度 × 叠加词变化），拖拽手感立刻上来。

### 方案 F：行程规划算法兜底（解决问题 1 算法层）

**文件**：`backend/app/agents/itinerary_agent.py`

**修改**：

1. **空结果兜底**（`plan` 方法末尾，line 117 前）：如果 `selected` 长度为 0，放宽时间约束（+50%）重试一次；仍为 0 则**返回距离最近的 3 个 POI**，前端至少能看到内容。

2. **距离惩罚项改为 soft 约束**（`_select_next`，line 165-166）：当前是硬约束直接跳过。改为：
   - 硬约束：travel_time > remaining_time 才跳（停留时间允许部分超出，由后续截断）
   - scoring 里加一项 `time_fit_score = max(0, 1 - (travel_time + stay_time)/remaining_time)`，越贴合剩余时间越优

3. **出行模式降级**：如果 walk 模式返回空，自动用 bike 重试（15 km/h，travel_time 降到 1/3），这对 5km 外的 POI 救命。
